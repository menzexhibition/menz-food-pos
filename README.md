# MENZ 快餐店 · 项目说明

> 最后更新：2026-06-04

---

## 一、核心概念

用 AI 实时控制取餐台摆出量，把当天采购的食材在营业时间内刚好卖完，换取最多客流。

**AI 的不可替代价值：**
> 实时控制「保温台剩多少」÷ 「在店人数」≤ ¥9/人（正价 ¥18 的 50%）

没有 AI，这一步靠人工做不到 — 人眼+经验响应太慢，无法实时调节。

---

## 二、商业模型

### 菜品结构

| 档位 | 说明 | 定价 |
|------|------|------|
| B 档 | 自选主菜（3-4道）| ¥18 正价 |
| C 档 | 半荤素菜（3-4道）| 含在 B 档 |
| E 档 | 免费汤饭 | 不限量 |
| A 档 | 广东风味招牌菜（+F3翻炒）| ¥5 加购任吃 |

每天选 2 道 A 档（1 翻炒 + 1 蒸箱），A 档是营销工具/招牌菜，不是盈利主力。

### 阶梯定价

| 时段 | 价格 |
|------|------|
| 11:00-11:30 / 17:00-17:30 | ¥15 |
| 11:30-13:00 / 17:30-19:00 | ¥18（正价） |
| 13:00-13:30 / 19:00-19:30 | ¥16 |
| 13:30-14:00 / 19:30-20:00 | ¥14 |
| 14:00-14:30 / 20:00-20:30 | ¥12 |
| 14:30-15:00 / 20:30-21:00 | ¥10 |
| 15:00+ / 21:00+ | 赠送（公益餐） |

**目的：削峰填谷，引导错峰，不是吸引老人走出家门。**

### 采购上限

**¥2,000/天**（固定采购上限，不是按人头浮动）

目标是尽量用完这 ¥2,000 的食材，同时不浪费。

---

## 三、赠送策略

**赠送对象不限于居委会，可以是：**
- 快递小哥、外卖员（高流动性，传播广）
- 环卫工人（固定时间，存在感强）
- 附近上班族（潜在转化）
- 居委会/街道（社区关系）

**赠送的量由 AI 决定**（保温台剩余量 ÷ 在店人数），不是固定数量。

---

## 四、关键约束（重要）

### 数据约束
- menu_db.js 里所有 `cost_estimate` 字段为**估算值，非真实采购数据**
- 不能用这些数字做财务决策
- 需要实际去菜市场/供应商询价后才能重建财务模型

### 关系约束
- 目前没有社区关系，居委会渠道需要从头建立
- **不做"社区刚需食堂"定位**，做"实惠快餐 + B2B 渠道"两条腿走路

### 人员约束
- Benny 目前独立运营 MENZ（展厅业务）
- 同时做 MENZ + 快餐 + 科技公司 = 最大风险点
- 需优先明确优先级

---

## 五、AI 动态出餐系统状态

- **技术风险：无商业先例**
- 重量传感器方案：技术成熟但成本高、误报率高
- 视觉识别方案：遮挡/蒸汽干扰问题待解决
- 需要找技术合伙人共同研发
- 是最大技术风险，也是最大差异化壁垒

---

## 六、战略路径（3年）

```
快餐模型跑通（证明 AI 出餐有效）
  → 融资 or 找技术合伙人
    → 开放加盟 = 科技公司
      → AI 系统对外输出
```

**前提：先有一家真实门店 + 3-6 个月运营数据**
