# MENZ 快餐店 · 项目说明

> 最后更新：2026-06-04

---

## 一、核心概念

用 AI 实时控制各档位菜品的投放节奏，把当天采购的食材在营业时间内刚好卖完，换取最多客流。

**AI 的不可替代价值：**
> 根据 POS 买单速度，动态决定 A 档招牌菜的投放节奏 — 人多就持续补，人少就暂停

没有 AI，这一步靠人工做不到 — 人眼判断客流太慢，无法精准控制出菜时机。

---

## 二、完整系统框架

系统分为四个独立模块，数据单向流动：

```
① 食材采购系统
    │ 决定今天有什么菜
    ▼
② 收银系统（中控）
    │ 收钱 + 记录交易 + 推送数据
    ▼
③ 后台控制系统
    │ AI 计算客流速度 + 决策出菜节奏
    ▼
    ├──→ ④ 后厨电视（F3 三屏指令）
    └──→ ④ 前台广告大屏（今日菜单 + 价格 + 倒计时）
```

| 模块 | 作用 |
|------|------|
| ① 食材采购系统 | 每日采购计划、¥2,000/天上限、库存管理 |
| ② 收银系统（中控）| 输入套餐+收款、记录交易、推送数据、中控 |
| ③ 后台控制系统 | AI 决策 A 档出菜节奏、输出 F3 指令 |
| ④ 前台广告显示 | 今日菜单、当前折扣价、距赠送倒计时、下一档预告 |

## 三、菜品与定价

### 菜品结构

| 档位 | 说明 | 定价规则 |
|------|------|---------|
| B 档 | 自选主菜（3-4道）| 按时段阶梯收费 |
| C 档 | 半荤素菜（3-4道）| 含在 B 档 |
| E 档 | 免费汤饭 | 不限量 |
| A 档 | 广东风味招牌菜（F3翻炒 + 蒸箱，每天2道）| 按规则浮动 |

每天选 2 道 A 档（1 翻炒 + 1 蒸箱），A 档数量有限，不支撑全天候持续供应。

### A档供应规则

| 时段 | B档 | A档 |
|------|-----|-----|
| 11:00-11:30 / 17:00-17:30 | ¥15 | 无供应 |
| **11:30-13:00 / 17:30-19:00** | **¥18（正价）**| **+¥5 加购**（有就卖）|
| 13:00-13:30 / 19:00-19:30 | ¥16 | **按¥16价格吃**（若有余货）|
| 13:30-14:00 / 19:30-20:00 | ¥14 | **按¥14价格吃**（若有余货）|
| 14:00-14:30 / 20:00-20:30 | ¥12 | **按¥12价格吃**（若有余货）|
| 14:30-15:00 / 20:30-21:00 | ¥10 | **按¥10价格吃**（若有余货）|
| 15:00+ / 21:00+ | 赠送 | **赠送**（若有余货）|

**A档核心逻辑：**
- 正价时段：卖的是"优先权"，+¥5 加购
- 非正价时段：卖的是"清库存"，按当前折扣价
- 本质：正价卖贵，非正价清货

### 采购上限

**¥2,000/天**（固定采购上限，不是按人头浮动）

目标是尽量用完这 ¥2,000 的食材，同时不浪费。

## 四、AI 动态出餐系统

### 核心输入
**POS 买单速度**（不买传感器，靠收银数据）

买单间隔短 → 人多；买单间隔长 → 人少。

### AI 介入逻辑

#### A 档出菜节奏控制（核心 AI 决策）

> A 档 = 广东风味招牌菜，成本高，必须 AI 控制投放节奏

| 客流情况 | 判断 | AI 动作 |
|---------|------|---------|
| 买单不停 | 客人持续进来，人多 | F3 持续炒，A 档不断补（每批 10 人份）|
| 买单稀疏 | 客人断断续续，人少 | 暂停 A 档，等客流恢复再放 |
| 客流恢复 | 买单速度回升 | 重新开始放 A 档 |

**AI 决策的是：下一批 A 档什么时候投放，不是投多少。**

每批 A 档固定 10 人份，不能拆分。控速度 = 控时间间隔。

#### 其他 AI 任务

| 任务 | 说明 |
|------|------|
| 阶梯定价自动切换 | 时间到达，自动切价格，无需人工操作 |
| 告警提醒 | 某个菜预计还能撑10分钟，提醒后厨准备下一批 |
| 补菜计划 | 根据历史消耗速度，提前安排下一批菜的备料时间 |

### 系统约束
- **不依赖传感器**，全部靠 POS 数据驱动
- 所有菜品按 10 人份生产/投放，不能拆分份量
- AI 是大脑，员工是执行手，AI 下指令，员工执行

## 五、POS 收银系统

### 系统架构

```
买单（POS）
  → AI 决策引擎
    → 后厨电视（分3屏）
      → 厨师照做
```

### 数据流

| 环节 | 内容 |
|------|------|
| POS 记录 | 每笔买单：时间、菜品、数量 |
| AI 计算 | 买单速度、各档位消耗速度 |
| AI 决策 | 下一批炒什么菜、哪台 F3 |
| 电视显示 | 机号 / 该炒什么 / 目标时间 |

### 后厨电视分屏示意

```
┌─────────────┬─────────────┬─────────────┐
│  F3 一号机  │  F3 二号机   │  F3 三号机  │
├─────────────┼─────────────┼─────────────┤
│  当前：     │  当前：     │  当前：     │
│  蒜蓉菜心   │  姜葱牛肉   │  四季豆肉末 │
│             │             │             │
│  下一道：   │  下一道：   │  下一道：   │
│  苦瓜牛肉   │  香菇滑鸡   │  — 等候中 — │
│             │             │             │
│  状态：就绪 │  状态：烹饪中│  状态：空闲 │
│  预计3分钟后│  剩余4分钟  │             │
└─────────────┴─────────────┴─────────────┘
```

### AI 决策逻辑

| 优先级 | 场景 | AI 动作 |
|--------|------|---------|
| P1 | 某个菜快没了 | 那台 F3 优先炒这道 |
| P2 | 哪台 F3 空着 | 分配下一道菜 |
| P3 | A 档菜待出 | 根据客流速度决定是否插队 |

### 厨师操作流程

1. 看电视 → 看到自己那台 F3 显示"该炒什么"
2. 备料 → 按配方准备食材
3. 投料 → 时间到，把菜放进 F3
4. 完成后 → 电视自动更新下一道指令

## 八、赠送策略

**赠送对象不限于居委会，可以是：**
- 快递小哥、外卖员（高流动性，传播广）
- 环卫工人（固定时间，存在感强）
- 附近上班族（潜在转化）
- 居委会/街道（社区关系）

**赠送的量由 AI 决定**（根据客流情况和剩余库存综合判断），不是固定数量。

## 九、关键约束（重要）

### 数据约束
- menu_db.js 里所有 `cost_estimate` 字段为**估算值，非真实采购数据**
- 不能用这些数字做财务决策
- 需要实际去菜市场/供应商询价后才能重建财务模型

### 关系约束
- 目前没有社区关系，居委会渠道需要从头建立
- **不做"社区刚需食堂"定位**，做"实惠快餐 + B2B 渠道"两条腿走路

### 人员约束
- Benny 目前独立运营 MENZ（展厅业务）
- 同时做 MENZ + 快餐 + 科技公司 = 最大风险点
- 需优先明确优先级

## 十四、全天运营流程（标准日）

```
08:00  AI分析当日食材价格
       → 确定菜谱（2道A档 + 4道B档 + 4道C档）
       → 按¥2,000预算分配采购量

08:00-10:30  食材陆续到店
              → 厨师分类处理、配菜
              → 配菜进度实时显示在后台

10:30  AI发出预热指令
       → F3三台同时预热
       → 厨师做最后备料

11:00  准时开业
       → 前台广告屏切换"营业中"
       → AI开始监控买单速度

11:00-11:30  优惠时段 ¥15
              → AI暂不开放A档
              → 先消耗B/C档库存

11:30-13:00  正价时段 ¥18 + A档+¥5
              → AI根据客流速度投放A档
              → 人多持续补，人少暂停

13:00-15:00  折扣时段（¥16→¥10）
              → A档按折扣价供应余量
              → AI控速

15:00-17:00  午休
              → 剩余熟食全部赠送（若有）
              → AI存档午市数据，决定下午菜量

17:00-21:00  晚餐（同中午逻辑）
              → 优惠→正价（A档）→折扣→赠送

21:00  全场赠送
       → 若有剩余食材继续供应
       → AI存档当日数据
```
